# RL / Preference Optimisation for Expressive TTS, and Frozen-Encoder + Adapter Prompt Pathways for Small TTS (2023–2026)

Notes compiled 2026-10-07. Convention: **[V]** = verified from the primary page (arXiv abstract/HTML/PDF) during this research; **[S]** = from search-engine summaries of the primary page (likely correct, details not read); **[R]** = recalled from prior knowledge, not re-verified in this session (check before citing).

## Q1. Which RL / preference methods have been applied to TTS, and how (model type, algorithm, rewards, hacking, gains)?

### Takeaway
Almost all published TTS RL is done on **AR codec-LM TTS** (DPO family 2024, GRPO/DiffRO 2025–26). Expressive/emotion RL that actually trains with an emotion reward exists (EMORL-TTS: GRPO with SER + VAD-intensity + F0/energy-emphasis rewards; DiffRO/RRPO in CosyVoice 3 with SER rewards; Emo-DPO, EASPO, Emo-LiPO, HPRO via preferences). Industrial RL stages (Inworld TTS-1) use only WER/SIM/DNSMOS; emotion rewards there are proposals, not results. A recurring finding: error-only rewards (WER/CER) flatten prosody, and naive emotion RMs get hacked with acoustic artefacts.

### Cited Findings

**Industrial / general-quality RL**
- [V] **Inworld TTS-1 / TTS-1-Max (arXiv 2507.21138, Jul 2025)**: 1.6B / 8.8B SpeechLM; pipeline = pre-training → SFT → RL alignment. Algorithm GRPO, advantage = reward − group mean with **no std scaling** (to avoid question-difficulty bias), clipped updates + KL to SFT reference; 8 samples per prompt; RL on 1,000 h English subset. Rewards: R_wer = exp(−2.5·WER) via Whisper-large-v3; R_sim = (cos+1)/2 with WavLM-large SV embeddings; R_dnsmos = (DNSMOS−1)/4; combined with α=β=γ=1. Emotion/style/non-verbal rewards are described only as conditional design proposals (applied to samples with matching annotations); **no emotion/arousal reward was trained or evaluated**; no reward hacking reported. English WER SFT→final: TTS-1 7.9→6.3, TTS-1-Max 6.9→5.1 (not isolated to RL). Style tags (8 styles, 7 non-verbals; ~100k examples/180 h/340 speakers) trained with **LoRA r=16, α=32, dropout 0.2**, LoRA chosen because it generalised better than full SFT — [arXiv HTML](https://arxiv.org/html/2507.21138v1), [abs](https://arxiv.org/abs/2507.21138)
- [V] **Inworld voice-steering blog (Tikhonov, 25 Sep 2026)**: the acoustic "direction" heuristics (Δ chars/sec; Δ RMS; Δ median voiced F0; Δ F0 IQR; final-300 ms voiced-F0 slope; silence/duration ratio for pauses; spectral-centroid p90−p10 for clear articulation; peak F0 + peak RMS in target window for emphasis; whisper = HF/LF energy + voiced-frame fraction + spectral flatness; nasal = 500–900 vs 150–350 Hz energy; melodic = voiced ratio + vibrato proxy) are used **for evaluation only, not training**. ~25 directions reduced to 16 in 7 groups; >100 English voices; evolutionary instruction search can maximise a heuristic or a composite "expressiveness" metric; heuristics are **not calibrated against each other**; LLM judges (Qwen, "Inkling") reach ~60% pairwise agreement with humans and hallucinate unheard properties; author notes high steerability isn't always desirable. No RL/reward details given — [altsoph Substack](https://altsoph.substack.com/p/wtf-is-voice-steering)

**DPO-family (2024–2025), AR codec LMs**
- [S] **SpeechAlign (Zhang et al., NeurIPS 2024, arXiv 2404.05600)**: iterative self-improvement for codec-LM TTS; preference pairs = golden codec tokens (preferred) vs model-generated tokens; compares CoH, DPO, RLHF-PPO, best-of-N; reported to work for smaller models — [arXiv](https://arxiv.org/abs/2404.05600v1), [NeurIPS](https://neurips.cc/virtual/2024/poster/95112)
- [S] **"Preference Alignment Improves Language Model-Based TTS" (Tian et al., CMU/Tencent, arXiv 2409.12403, 2024)**: mainly DPO on a 1.15B LM-TTS trained on 55k h; gains in intelligibility, speaker similarity and proxy subjective scores — [arXiv](https://arxiv.org/html/2409.12403v1)
- [S] **Koel-TTS (NVIDIA, EMNLP 2025, arXiv 2502.05236)**: preference alignment with ASR + speaker-verification-derived rewards, plus classifier-free guidance. Relevant because it is NeMo-ecosystem — [arXiv](https://arxiv.org/html/2502.05236v2)
- [S] **UNO / uncertainty-aware RLHF for TTS (Chen et al. 2024; likely arXiv 2406.00654 "Enhancing Zero-shot TTS with Human Feedback")**: accounts for variability in subjective perception; uses a KTO-style reference-point loss instead of paired DPO. Title/ID mapping NOT confirmed — [arXiv](https://arxiv.org/pdf/2406.00654)
- [S] **Fine-grained Preference Optimization (FPO, arXiv 2502.02950)**: localized/segment-level preference optimisation for zero-shot TTS — [arXiv](https://arxiv.org/pdf/2502.02950)
- [S] **Emo-DPO (Gao et al., A*STAR/NUS, arXiv 2409.10157, 2024)**: emotion-aware LLM-TTS; DPO pairs = same text, target emotion preferred over other emotions — [arXiv](https://arxiv.org/html/2409.10157v1). Critiqued by EASPO as endpoint-only/sparse supervision — [arXiv 2509.25416](https://arxiv.org/pdf/2509.25416)
- [S] **EASPO (arXiv 2509.25416, 2025)**: **diffusion TTS** with stepwise preference supervision from an emotion-aware preference model (one of few non-AR emotion preference methods) — [arXiv](https://arxiv.org/pdf/2509.25416)
- [V] **"No Verifiable Reward for Prosody" (Shin et al., ICASSP 2026, arXiv 2509.18531)**: GRPO on CER/NLL lowers error but "collapses prosody into monotone, unnatural speech"; adding a speaker-sim reward destabilised training and hurt CER. Fix: **iterative DPO regularised to the current model using a few hundred human-labelled preference pairs per round**; best ELO on Korean call-centre data with competitive CER, beating GRPO and commercial baselines — [arXiv](https://arxiv.org/abs/2509.18531)

**GRPO / RL with emotion rewards (2025–2026)**
- [V] **EMORL-TTS (Li et al., arXiv 2510.05758, v2 Jan 2026)**: base Spark-TTS (Qwen-based LLM + frozen BiCodec). Stage I SFT on ESD-English + 4,717 Expresso utterances with control tokens (emotion + weak/medium/strong). Stage II **GRPO, K=16, KL β=0.1 to SFT, lr 1e-6, 1,000 text sentences**, 8×RTX 4090. Reward = R_ser + R_int + R_emp: R_ser from emotion2vec SER (+5 match / −1 otherwise); R_int = distance of predicted VAD (Wagner et al. 2023 wav2vec2 dimensional model) from a neutral centroid, binned weak/medium/strong, hard bin match + Gaussian soft term; R_emp = per-word max log-F0 and mean STFT energy (NeMo Forced Aligner word boundaries), argmax indicators + clipped relative soft terms. Results: emotion acc 0.88 (vs 0.81 w/o GRPO, 0.63 CosyVoice2); intensity ordering accuracy ~0.65–0.72 vs 0.47–0.56 Emosphere++; emphasis acc 0.75; MOS 4.94 vs 4.92 w/o GRPO (no quality loss claimed); no quality reward and no hacking discussion; WER not reported — [arXiv HTML](https://arxiv.org/html/2510.05758v2)
- [S] **DiffRO — Differentiable Reward Optimization (CosyVoice 3, arXiv 2505.17589; standalone arXiv 2507.05911, 2025)**: rewards computed **on speech tokens, not audio**, to skip the flow-matching + vocoder stages (authors note post-vocoder audio becomes too similar to discriminate). Reward = posterior of a Token2Text (ASR-on-tokens) model; Gumbel-Softmax sampling lets gradients flow directly into the LM (no RL loop). Extended to a **multi-task reward (MTR)** model incl. SER and MOS prediction, enabling zero-shot emotion/quality attribute control; SOTA WER on seed-tts-eval — [CosyVoice 3](https://arxiv.org/html/2505.17589v2), [search summary of 2507.05911](https://proxy-ga.blitzz.co/proxy/123456/huggingface.co/papers/2507.05911)
- [V] **RRPO (Wang et al., Tongyi, ICASSP 2026, arXiv 2512.04552)**: builds on DiffRO for emotional LLM-TTS; **reports reward hacking**: the policy exploits a vanilla emotion RM by generating acoustic artefacts that earn spurious reward at the cost of perceptual quality. Mitigation = hybrid regularisation to make the RM robust/perceptually aligned; better expressiveness and naturalness in subjective tests; RM generalises cross-lingually — [arXiv](https://arxiv.org/abs/2512.04552)
- [S] **Emo-LiPO (arXiv 2606.13006, 2026)**: listwise preference optimisation for fine-grained emotion intensity in LLM-TTS — [arXiv](https://arxiv.org/pdf/2606.13006); **HPRO (arXiv 2606.28249)**: hierarchical progressive reward optimisation via preference extraction for emotional TTS — [arXiv](https://arxiv.org/pdf/2606.28249); **arXiv 2609.11523**: staged SFT + RL post-training of zero-shot TTS for per-segment emotion and duration control via natural language — [arXiv](https://arxiv.org/html/2609.11523v1). (Details not read.)
- [S] **EmoSteer-TTS (arXiv 2508.03543, Tencent/HKUST-GZ)**: training-free activation steering in flow-matching TTS (F5-TTS, CosyVoice2, E2-TTS): steering vector from activation differences between neutral and emotional reference speech over top-k emotion-relevant tokens, scaled by a strength parameter → continuous emotion conversion/interpolation/erasure — [arXiv](https://arxiv.org/abs/2508.03543)

**Related but not read**: [S] "Explore the RL for LLM-based ASR and TTS" (arXiv 2509.18569) — [arXiv](https://arxiv.org/html/2509.18569v1); [S] CosyVoice→Qwen-Audio-3.0-TTS staged-alignment retrospective (arXiv 2609.16514) — [arXiv](https://arxiv.org/pdf/2609.16514).

### Inferences
- The only paper found that trains with a reward set close to Whissle's (SER class + dimensional arousal/intensity + F0/energy heuristics) is EMORL-TTS; its recipe (SFT with discrete control tokens first, then GRPO K=16, β=0.1, small lr, ~1k prompts) is the most directly reusable template — but it is on a ~0.5B AR LM, not a ≤30M NAR model.
- Inworld's own RL (the blog's company) does not use the steering heuristics as rewards; using them as rewards would be novel and untested — treat them as eval + guard first.
- Expect two failure poles: error-only rewards → monotone (2509.18531); emotion-RM-only → artefacts/exaggeration (RRPO). Need both expressive and guard rewards plus KL.

### Gaps
- No verified per-paper hacking numbers for "shouting to max arousal"; RRPO reports artefact exploitation generically. The shouting/clipping mode is plausible but not cited.
- Did not read RIO (recalled: "Reverse Inference Optimization", arXiv 2407.02243 [R]), GRPO results in Llasa/Step-Audio/Spark RL, or DiffRO's standalone paper body.
- Inworld TTS-2 RL details (if any) not public in sources found.

## Q2. How can rewards be applied to NON-autoregressive / flow-matching small TTS? Tradeoffs and compute.

### Takeaway
Four proven routes: (1) **Flow-GRPO-style ODE→SDE GRPO** on the flow model (F5R-TTS, FlowTTS-GRPO); (2) **GRPO on a discrete/stochastic sub-module** such as the duration predictor (DMOSpeech 2); (3) **direct differentiable reward backprop** through a few-step generator/vocoder (DMOSpeech 1 [R]; DiffRO does it in token space); (4) **best-of-N with an external scorer** (ParaSpeechCLAP) optionally followed by distillation/rejection-sampling FT. For a ≤30M model, (3)+(4) are cheapest; (1) requires multi-step SDE sampling per group.

### Cited Findings
- [S] **F5R-TTS (arXiv 2504.02407, 2025)**: GRPO on flow-matching F5-TTS (made probabilistic); rewards = ASR WER + speaker similarity; no emotion reward — [arXiv](https://arxiv.org/abs/2504.02407)
- [V] **FlowTTS-GRPO (Wang et al., Tongyi, Interspeech 2026, arXiv 2606.23190)**: online RL converting ODE sampling trajectories into SDE paths to fine-tune open-source FM TTS (CosyVoice 3 FM stage, F5-TTS) without auxiliary models; rewards = speaker sim, perceptual quality, intelligibility; **weighted reward sum converged faster than a probabilistic (sampled-reward) scheme**; **dropping CFG during RL training speeds convergence**; synthesising hard cases improves robustness; RL on the FM component improves audio-detail metrics — [arXiv](https://arxiv.org/abs/2606.23190)
- [S] **Flow-GRPO (arXiv 2505.05470)**: the base ODE→SDE GRPO technique (text-to-image) — [arXiv](https://arxiv.org/pdf/2505.05470); **GRPO-Guard (arXiv 2510.22319)**: regulated clipping to mitigate implicit over-optimisation in flow-matching GRPO — [arXiv](https://arxiv.org/pdf/2510.22319); **"Rethinking Reward Signals in Video GRPO: When Scores Become Targets" (arXiv 2511.19356)** — Goodhart effects in flow GRPO — [arXiv](https://arxiv.org/pdf/2511.19356)
- [V/S] **DMOSpeech 2 (Li et al., Columbia/NewsBreak, AAAI 2026, arXiv 2507.14988)**: GRPO applied only to the **duration predictor** (transformer enc-dec predicting total remaining length as 300-class distribution, 100 ms bins up to 30 s; CE pretrain then GRPO) with ASR WER + SV similarity rewards; plus teacher-guided sampling (teacher for early steps, student after) → better diversity, half the steps. Code: github.com/yl4579/DMOSpeech2 — [arXiv](https://arxiv.org/html/2507.14988v1), [AAAI](https://ojs.aaai.org/index.php/AAAI/article/view/40450)
- [R] **DMOSpeech (arXiv 2410.11097, 2024)**: distils a diffusion/flow TTS into a few-step student so that CTC (ASR) and speaker-verification losses can be **backpropagated end-to-end** through generated audio — direct metric optimisation without RL. (Recalled; verify.)
- [S] DiffRO avoids backprop through FM+vocoder by scoring tokens; authors say post-vocoder samples are too similar to separate good/bad — [CosyVoice 3](https://arxiv.org/html/2505.17589v2)
- [V] **ParaSpeechCLAP (Diwan, Choi, Harwath, arXiv 2603.28737, Mar 2026)** as **inference-time reward (best-of-N, N=10)** for style-prompted TTS: consistency CMOS 3.61→3.70, intrinsic tag recall 57.9→62.4%, situational 69.2→74.3%, naturalness MOS 3.34→3.35, WER 8.14→7.56; cost linear in N — [arXiv HTML](https://arxiv.org/html/2603.28737v1)
- [V] EmoSteer-type activation steering is a no-training alternative for FM models — [arXiv](https://arxiv.org/abs/2508.03543)

### Inferences
- For a ≤30M FastSpeech/VITS/small-FM model whose prosody comes from explicit predictors (duration, F0, energy), the highest-leverage target is the **variance adaptor**: run DMOSpeech-2-style GRPO on stochastic duration/pitch/energy heads (cheap: only the small predictor is updated; rewards from heuristics are essentially free), leaving the decoder/vocoder frozen.
- Differentiable heuristics (RMS, frame-level F0 from a differentiable pitch tracker or the model's own predicted F0, spectral flatness on mel) and a differentiable WavLM-probe SER can be backpropped through a 1-step generator + vocoder (DMOSpeech-style). Cheapest per step but most hack-prone (adversarial artefacts — cf. RRPO); needs frozen-vocoder + KL/feature-matching to SFT output.
- Best-of-N with the full reward stack (heuristics + Whissle ear + WER/SIM/UTMOS guards) → keep winners → SFT/distil ("rejection-sampling FT") is the lowest-risk first step and produces DPO pairs for free.
- Flow-GRPO for a tiny FM model is feasible but each group needs K×(SDE steps) forward passes plus vocoding + scoring; drop CFG during RL (FlowTTS-GRPO) to halve cost.

### Gaps
- No paper found applying GRPO/DPO to a ≤30M TTS specifically; scaling of these results down is unverified.
- No compute (GPU-hours) figures found for F5R-TTS / FlowTTS-GRPO.

## Q3. Using non-differentiable acoustic heuristics as rewards: multi-reward balancing, regularisers, guards, hacking

### Takeaway
Use a weighted sum of normalised rewards with group-relative advantages (no std scaling per Inworld), KL to the SFT policy, and hard guards on WER/SIM/quality; make expressive rewards **directional and bounded** (bins/Gaussian targets, clipping) rather than "maximise". Evidence of hacking: artefact-generation against emotion RMs (RRPO) and monotone collapse under error-only rewards (2509.18531).

### Cited Findings
- [V] Inworld normalises each reward to [0,1] (exp(−k·WER), (cos+1)/2, (DNSMOS−1)/4), sums with equal weights, uses mean-centred advantages without std scaling, KL to SFT — [arXiv](https://arxiv.org/html/2507.21138v1)
- [V] EMORL-TTS turns intensity into **binned targets with Gaussian soft term** and emphasis into **clipped relative** pitch/energy terms (bounded rewards, not open-ended maximisation); KL β=0.1; MOS preserved — [arXiv](https://arxiv.org/html/2510.05758v2)
- [V] FlowTTS-GRPO: weighted reward sum > probabilistic reward selection for convergence — [arXiv](https://arxiv.org/abs/2606.23190)
- [V] RRPO: vanilla emotion RM hacked via acoustic artefacts; fix by regularising/robustifying the RM — [arXiv](https://arxiv.org/abs/2512.04552)
- [V] Error-only GRPO → monotone prosody; SIM reward destabilises; small human-preference iterative DPO fixes — [arXiv](https://arxiv.org/abs/2509.18531)
- [V] Inworld blog: heuristics uncalibrated across directions; LLM judges ~60% agreement with humans — [Substack](https://altsoph.substack.com/p/wtf-is-voice-steering)
- [S] GRPO-Guard / video-GRPO Goodhart papers document over-optimisation in flow GRPO generally — [2510.22319](https://arxiv.org/pdf/2510.22319), [2511.19356](https://arxiv.org/pdf/2511.19356)

### Inferences
- Concrete reward design for Whissle (inference, not from a paper): r_dir = clip(sign_d·(feat(y) − feat(y_neutral_same_text_same_voice)) / τ_d, 0, 1) per instructed direction (relative to a neutral rendering, exactly as the blog's Δ metrics), plus r_ear = SER/arousal probe target match (binned like EMORL), plus guards as multiplicative gates or large penalties: WER > threshold → 0, SIM < threshold → 0, UTMOS drop > δ → 0. Also penalise off-target directions (e.g., "slower" must not change loudness/F0 beyond tolerance) to avoid "do everything louder" shortcuts.
- Anticipated hacks for listed heuristics: loudness/arousal → clipping/shouting (guard with peak/clipping detector + UTMOS); pause ratio → inserting long silences or trailing silence (trim edges, cap per-pause length); F0 IQR → octave jumps/pitch-tracker errors (use voiced-confidence filtering, cap); whisper via spectral flatness → noise (guard with WER + UTMOS); final-slope → single-frame glitches (fit over voiced frames only); Whissle ear → adversarial artefacts (RRPO) — ensemble/augment the probe and keep it out of the training loop for evaluation (hold-out RM).
- Hold out at least one reward (e.g., a different SER model or human A/B) purely for evaluation to detect Goodharting.

### Gaps
- No published study found using the exact Inworld heuristic set as RL rewards; hacking rates per heuristic are unmeasured.
- UTMOS as a guard in TTS RL was not found in verified sources (DNSMOS used by Inworld).

## Q4. Frozen pretrained encoders + small adapters as the prompt/style pathway for a small TTS

### Takeaway
Frozen text encoder + linear/MLP projection is the standard prompt pathway (PromptTTS/PromptStyle with BERT, Parler-TTS with frozen Flan-T5 [R], Prompt-Singer with frozen encoder + linear layer). Prompt-Singer's controlled comparison shows gains saturate quickly with encoder size (FLAN-T5 small→base is the big jump; large≈XL), BERT-base is competitive, and **fine-tuning the encoder on label prediction helps more than scaling** — which supports caching a frozen ~20–110M sentence encoder plus a trained adapter, or distilling labels into it.

### Cited Findings
- [V] **Prompt-Singer (arXiv 2403.11780; NAACL 2024 [R for venue])**: "parameter-frozen text encoder ... followed by a linear layer" into the transformer; compared FLAN-T5 small/base/large/XL, BERT-base/large, CLAP-general / CLAP-speech-music. Gender accuracy (F/M): T5-small 76.7/78.1, T5-base 82.2/79.5, T5-large 83.1/80.8, T5-XL 83.4/80.4, BERT-base 80.8/80.1, BERT-large 84.9/80.9, CLAP 82.2/79.5 and 82.2/78.1; fine-tuned T5-large 87.7/86.3, fine-tuned BERT-large 86.3/83.6. Authors: larger is generally better but "text encoder parameters beyond a certain size are no longer a bottleneck"; fine-tuning encoders on prompt→label gives +4.6/+5.5 (T5-large) gender acc.; T5 weaker on volume than CLAP/BERT by 1.2–2.3 points, better on vocal range — [arXiv PDF](https://arxiv.org/pdf/2403.11780)
- [S] **PromptStyle (Liu et al., Interspeech 2023, arXiv 2305.19522)**: improved VITS + cross-modal style encoder; stage 2 maps BERT prompt embeddings to a pretrained style-embedding space via cosine loss, **training only BERT's last attention layer**, style encoder frozen; ~6 h of description-labelled data — [arXiv](https://arxiv.org/pdf/2305.19522), [ISCA](https://www.isca-archive.org/interspeech_2023/liu23t_interspeech.pdf)
- [S] Parler-TTS style token from frozen Flan-T5 reused downstream via **linear projection + FiLM and prefix tokens** (Clarity 2025, speech separation, not TTS) — [ISCA](https://www.isca-archive.org/clarity_2025/rahimi25_clarity.pdf)
- [S] Frozen StyleTTS 2 + tiny MLP adapter mapping an external embedding to its 128-d style vector (face-to-speech, 2026) — [alphaXiv 2607.26742](https://www.alphaxiv.org/abs/2607.26742)
- [V] **ParaSpeechCLAP**: WavLM-Large (~317M) speech tower + Granite-Embedding-278M text tower, 2-layer GELU+LN projection heads to 768-d; vastly better than **ParaCLAP** (wav2vec2 + BERT, MSP-Podcast, 6 situational tags) on style retrieval (situational R@1 24.79 vs 0.41; R@10 88.82 vs 3.98). Not used as TTS conditioning, only as a scorer — [arXiv HTML](https://arxiv.org/html/2603.28737v1)
- [V] Inworld uses LoRA (r=16) for style-tag capability on top of a frozen-ish SFT model; LoRA generalised better than full SFT — [arXiv](https://arxiv.org/html/2507.21138v1)
- [R] **PromptTTS (Guo et al., ICASSP 2023, arXiv 2211.12171)**: BERT-based style encoder on prompts; **PromptTTS 2 (arXiv 2309.02285)**: variation network + LLM-generated prompts; **Parler-TTS / "Natural language guidance of high-fidelity TTS with synthetic annotations" (Lyth & King, arXiv 2402.01912)**: frozen Flan-T5 encoder, description fed via cross-attention to a decoder-only codec LM; **ControlSpeech (arXiv 2406.01205)**: decoupled codec + style mixture semantic density module for prompt-to-style one-to-many; **InstructTTS** (cross-modal representation learning). All recalled, not re-verified this session.

### Inferences
- For a controlled vocabulary of directions (≈16–50 steering directions × intensities, plus free-text paraphrases), the frozen encoder can run **offline once**: cache embeddings for all training prompts and for a paraphrase bank; at inference either look up cached vectors or run a ~22M MiniLM on CPU (negligible latency). The TTS then only owns a small adapter (e.g., 2-layer MLP → FiLM/γβ on variance adaptor and decoder, or K prefix tokens) — a few hundred K params, consistent with the ≤10–30M budget.
- Prompt-Singer suggests a ~60–110M encoder (T5-base/BERT-base class) is near the knee; a 22–33M MiniLM/BGE-small is untested in TTS but the bigger lever is **aligning the encoder/adapter to labels** (fine-tune or train adapter with auxiliary prompt→attribute classification loss; PromptStyle-style cosine alignment to a reference-audio style space).
- Distillation path: use a large encoder/LLM planner offline to map free text → structured control vector (direction deltas, emotion, intensity) and train the small adapter (or a tiny student encoder) to regress it; at runtime only the student runs.
- Reference-audio style: a frozen small SSL encoder (WavLM-base+/emotion2vec-base, mean-pooled) + projection into the same style space as the text adapter (PromptStyle two-stage) lets the "Whissle ear" and the style pathway share representation; but sharing the reward model's backbone with the conditioning pathway increases hack risk — keep the reward probe separate or held out.
- CLAP-style towers (ParaSpeechCLAP) appear more valuable as **rewards/rerankers** than as conditioning; ParaCLAP's weak retrieval suggests older paralinguistic CLAPs are poor text towers for fine style.

### Gaps
- No verified study of MiniLM/BGE/E5-sized frozen encoders in prompt-TTS; encoder-size evidence is from singing (Prompt-Singer) only.
- Q-Former-style connectors for TTS style prompts not found in this session.
- Parler-TTS, PromptTTS 1/2, ControlSpeech details are recalled; verify IDs before citing.
